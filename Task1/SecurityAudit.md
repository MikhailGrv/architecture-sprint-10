# Аудит мер по обеспечению безопасности данных

## Выявленные группы данных

### Персональные данные (далее - PII): ФИО,  дата рождения (в связке с другим идентифицирующим аттрибутом, например ФИО), Телефон, эл. почта, история болезни + PII, анализы +PII (далее - ПД) - Требования законодательства РФ 152-ФЗ

### Внутренние/Конфеденциальыне данные: история болезней (без PII), анализы (Без PII)  - ценность компании, необходима для осуществления деятельности

### Коммерческие данные: платежи, финансовая и складская информация - ценность компании, необходима для осуществления деятельности

## Список проблемных зон

### PII 

    1. Храненение в общем доступе сотрудников компании - риск компроментации, 
    2. Избыточноть храннения информации
    3. Незащищенные даныне в работе, при передаче, при хранении
    4. Нет ограничения доступа (например ролевой модели)
    5. PII храняться вместе с мед. информацией 
    6. Риски потери данных
    7. Риски нарущения целостности
    8. Риски искажения данных

### Внутренние/Конфеденциальыне данные: Храненение в общем доступе сотрудников компании - риск компроментации
    
    1. Хранение данных в общедоступном месте
    2. Риски потери данных
    7. Риски нарущения целостности
    8. Риски искажения данных
    9. Риски компроментации
    10. Незащищенные даныне в работе, при передаче, при хранении
    11. Нет ограничения доступа (например ролевой модели)

### Коммерческие данные: следует детальнее изучить настройки прав доступа в 1С-бухгалтерии и Торговле+Склад, а также передачи и хренениея информации (шифрование, минимальность)

## Что можно улучшить

### Применить подход Privacy by Design

Координальный подход, потребующий изменения архитектуры системы. 
Разделить PII и стория болезней (без PII), анализы (Без PII) применяя идетификаторы вместо PII
Применить RBAC/ABAC для ограничения доступа к необходиым функциям и данным для выполнения конкретной функции (ZeroTrust)
Отменить сбор и хранение необязательной ифнормации адресе прописки  месте работы или учёбы (Data Minimization)
Хранение данных в системах, позволяющих цифровать данные (например СУБД Postgres), разделить хранение PII и остальной информации на физическом уровне с органичением доступа. 
Хранение PII должно быть ограничено сроком в соответсвии с закорном РФ и на территории РФ.
Длительность храненения данных применить к Мед. картам.
Передача данных должна осуществляться по защищеннным каналам (например TLS 1.2)
На сторону пользователя (Ресепшен, Медецинский специалист) передавать данные только необходимые для выполнения конкретной задачи.
Применять Маскирование там, где данные не требуются для выполнения функции

### Быстрые решения 
в AD добавить роли
Ограничить ролям доступ в общую папку, только к тем файлам, которые нужны (например карты видят только мед. специалисты, журнал посещения (графики) видят Ресепшен + мед специалисты (PII должны быть маскированы))
Перестать собирать необязательную информацию о клиентах
Удалить устаревшие данные

### Дополнительные решения к Быстрым решениям

Внедрить систему тэгирования данных, которая будет проверять общую паппку, маркировать данные 
За тем эмаркированные данные должны быть распределены в соответсвии с Ролевой моделью. Там, где не требуется PII (например графики посещений) - маскировать данные.

## Важно: если не менять дизайн системы, то добиться полного соотверствия 152-ФЗ и снижению рисков будет крайне затруднительно.
